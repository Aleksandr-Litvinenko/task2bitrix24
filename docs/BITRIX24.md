# Работа с Bitrix24

Сервис использует входящий webhook Bitrix24 REST API. Реальный URL webhook не хранится в репозитории.

Webhook задаётся одним из способов:

- переменная окружения `BITRIX_WEBHOOK`;
- локальный файл `task2/config.local.php`, который игнорируется git.

Пример формата:

```text
https://<portal>.bitrix24.ru/rest/<user-id>/<webhook-code>/
```

## Транспорт

Все запросы выполняются POST-запросами с `application/x-www-form-urlencoded`.

Базовая схема:

```php
$url = rtrim(BITRIX_WEBHOOK, '/') . '/' . ltrim($method, '/');
$body = http_build_query($data);
```

Код использует `curl`, если расширение доступно, иначе fallback на `file_get_contents()` со stream context.

Если Bitrix возвращает `QUERY_LIMIT_EXCEEDED`, запрос повторяется с паузой. Массовые запросы идут через `batch`, по 50 команд в одном chunk.

## Методы Bitrix24

### `tasks.task.list`

Используется для получения задач по закрытию:

- `>=CLOSED_DATE`
- `<=CLOSED_DATE`
- `REAL_STATUS`

Выбираемые поля:

- `ID`
- `TITLE`
- `STATUS`
- `REAL_STATUS`
- `CREATED_DATE`
- `CREATED_BY`
- `RESPONSIBLE_ID`
- `CLOSED_DATE`
- `UF_CRM_TASK`
- `UF_AUTO_692242927731`
- `UF_AUTO_899199298816`

Пагинация идёт через `start`. Дополнительные страницы запрашиваются через `batch`.

### `tasks.task.result.list`

Используется для чтения результата завершённой задачи. Сервис берёт `text` или `formattedText`, чистит HTML/Bitrix-разметку и ищет дату выполнения работ.

Главное правило: отчётный месяц определяется датой внутри результата задачи, а не датой закрытия задачи.

Примеры поддерживаемого текста:

```text
дата выполнения работ 07.06.2026
Дата выполнения задачи 07.06.2026
07.06.2026
```

### `task.elapseditem.getlist`

Используется для получения списанного времени по задаче.

Фильтр:

- `TASKID`
- `FILTER.USER_ID` со списком сотрудников отчёта

Поля:

- `ID`
- `TASK_ID`
- `USER_ID`
- `MINUTES`
- `COMMENT_TEXT`

Часы считаются только из `MINUTES`. Комментарии не используются как источник часов.

### `user.get`

Используется для отображения ФИО сотрудников по Bitrix user ID.

### `crm.company.list`

Используется для получения названия компании по ID из `UF_CRM_TASK`.

## Правила отчёта

1. Пользователь выбирает месяц и год.
2. Сервис смотрит задачи, закрытые с запасом 7 дней до начала выбранного месяца и 7 дней после конца месяца.
3. Берутся только задачи со статусами `REAL_STATUS` 4 и 5.
4. Для каждой задачи читается результат.
5. В отчёт попадает только задача, где дата в результате находится в выбранном месяце.
6. По попавшим задачам читаются списания времени.
7. Время относится к тому сотруднику, кто списал время (`USER_ID` в elapsed item).
8. Итоги суммируются по сотрудникам и по задачам.

## Excel

Файл создаётся без сторонних PHP-библиотек, напрямую как `.xlsx` ZIP-пакет с XML-частями.

Листы:

- `Свод`;
- лист по каждому сотруднику;
- `Все задачи`.

На листе `Все задачи` поля задачи заполняются в каждой строке, чтобы фильтры Excel работали по всем строкам списаний. Задачи визуально отделяются рамками и чередующейся заливкой.
